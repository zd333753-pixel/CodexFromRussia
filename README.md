# Codex VPS Launcher

Windows-приложение для запуска Codex и отдельного окна Chrome/Edge через собственный SSH-сервер. SSH создаёт локальный SOCKS5-прокси; для сетевого процесса Codex используется HTTP CONNECT поверх того же туннеля. TLS остаётся зашифрованным между клиентом и сайтом.

Это сторонний проект, не официальный продукт OpenAI. Нужны установленный Codex, Chrome или Edge и собственный доступный VPS. Приложение не меняет региональную доступность сервисов и не гарантирует доступ с любого IP.

## Сборка

Windows 10/11, .NET Framework 4.5+ (рекомендуется 4.8), компонент Windows OpenSSH Client и curl.exe.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Результат: `dist/CodexVpsLauncher.exe`. Скопируйте `connection.example.ini` в `dist/connection.ini` и заполните параметры. EXE не подписан; Windows может показать предупреждение SmartScreen.

## Подключение

Создайте отдельный SSH-ключ для туннеля:

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\codex_proxy"
```

Для текущей версии требуется ключ без парольной фразы; храните его только в личном профиле Windows. На сервер переносится только файл `.pub`. Подготовка сервера описана в [docs/server.md](docs/server.md).

Один раз подключитесь интерактивно и проверьте отпечаток сервера через доверенный канал (например, консоль хостинга). Только после проверки подтвердите host key:

```powershell
ssh -N -p 443 -i "$env:USERPROFILE\.ssh\codex_proxy" codex-tunnel@YOUR_SERVER_IP
```

После успешного подключения нажмите Ctrl+C. Программа использует `StrictHostKeyChecking=yes` и не принимает неизвестные ключи автоматически.

## Использование

1. Полностью закройте обычный Codex, запустите `CodexVpsLauncher.exe`.
2. Нажмите «Проверить туннель»: ожидается внешний IPv4 из `ServerIp`.
3. Нажмите «Запустить Codex».
4. При входе скопируйте полную свежую ссылку авторизации из обычного браузера в поле запускателя и нажмите «Открыть браузер через VPS». Ссылки авторизации не публикуйте.
5. Держите запускатель открытым во время работы. «Остановить» или закрытие запускателя выключает туннель.

Браузер использует отдельный профиль `%LOCALAPPDATA%\CodexVpsBrowser`. Он и запущенные дочерние процессы Codex используют туннель. Обычные окна браузера и системный прокси не перенастраиваются. Localhost обходится напрямую для возврата авторизации в Codex.

## Ограничения

- Локальные порты 18080 и 18081 должны быть свободны; запускайте одну копию программы.
- Codex обнаруживается как пакет Microsoft Store `OpenAI.Codex`.
- Проверка IP предполагает, что исходящий IPv4 сервера совпадает с его SSH-адресом; VPS с отдельным NAT-адресом потребует доработки.
- HTTP CONNECT обслуживает HTTPS на порту 443; обычный HTTP через него не поддерживается.
- Нет автоматического перехвата ссылок входа и автоматического переподключения при потере SSH.
- После открытия браузера туннель сохраняется до остановки запускателя, даже если Codex закрыт. Сам браузер при остановке не закрывается.
- Результат авторизации зависит от доступности OpenAI и текущей версии Codex.

## Проверка

Исходная персональная сборка прошла проверку SSH и HTTP CONNECT: HTTPS-запрос вернул IPv4 VPS. Пользователь сообщил, что Codex предположительно работает через туннель. Это не полноценное тестирование на разных компьютерах. Публикуемая версия использует конфигурационный файл вместо личных адресов и ключей.
